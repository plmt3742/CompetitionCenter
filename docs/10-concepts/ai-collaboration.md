# AI 协同与资料收集

## 立场

系统本身**不调用大模型**。AI 是个人工具链的一部分，系统负责"收集、登记、复核、入档"这四件事。

理由：

- 部门资料含大量个人信息与未公开结果，集中调用第三方模型风险不可控。
- 模型输出需要人判断，自动归档会把错误固化。
- 成员已经各自在用 AI 工具，强制迁移到系统内反而增加负担。
- 系统保持简单，维护成本低，换届后更容易接手。

## 流程

```text
收到资料 → 收集箱登记（≤3 个必填字段）
        → 归类（赛事/阶段/类型/密级）
        → 个人处理（摘要、OCR、改名、拆分）
        → 人工复核（负责人确认内容与密级）
        → 入档（生成正式条目，记录处理链）
        → 发布（仅 L1，经审校）
```

关键点：**收集与入档分离**。收集可以很随意，入档必须干净。

## 收集箱字段

必填只有三个：

1. 标题（这是什么）
2. 来源（从哪来：群聊/邮件/网盘/现场/其他）
3. 密级（拿不准选更高）

其余可后补：关联赛事、阶段、类型、处理人、备注、原始位置。

设计目标：从手机到登记完成不超过 30 秒；支持拍照、贴链接、转发文件。

## 处理链

每个收集项记录：

| 字段 | 说明 |
|---|---|
| 处理人 | 谁整理的 |
| 处理日期 | 何时 |
| 使用工具 | 哪个 AI/软件（可空） |
| 原稿位置 | 原始文件在哪（L3/L4 不写公开位置） |
| 产出条目 | 生成了哪些正式档案 |
| 复核人 | 谁确认内容与密级 |
| 复核日期 | 何时 |

处理链的目的不是监控，而是回答"这份档案是怎么来的、能不能信"。

## 允许与禁止

| 场景 | 允许 | 禁止 |
|---|---|---|
| L1 公开资料 | 任意工具摘要、改写、翻译 | 编造事实、伪造来源 |
| L2 内部资料 | 本地或已脱敏后处理 | 上传含内部排期的原文到公开模型 |
| L3 个人信息 | 本地模型或脱敏后处理 | 上传报名表、成绩、联系方式原文 |
| L4 赛题/评审 | 本地模型；最小范围 | 上传第三方模型；在公开对话中讨论 |

补充规则：

- 模型生成的数字、排名、结论不得直接作为正式结果。
- AI 生成的图片/文案用于对外发布前必须人工审校，并确认版权与肖像。
- 提示词与工具变更记录在 `.agent/90-meta/prompts/README.md`（本地）。

## 质量门槛

一条资料可以入档，至少满足：

1. 标题能让人知道是什么。
2. 关联到正确的卷宗与阶段。
3. 密级正确。
4. 有负责人。
5. 有来源或处理链。
6. 内容经过人复核。

不满足的记录留在收集箱，不进入正式档案。

## 为什么不做系统内 AI

| 方案 | 问题 |
|---|---|
| 自动摘要/自动分类 | 错误会静默进入档案；隐私边界难控 |
| 自动 OCR 全量扫描 | 成本与存储高；大量资料其实不需要 |
| 对话式问答档案 | 检索问题可以用结构化查询解决，先不引入模型 |
| 自动生成通知/推文 | 对外口径需要人负责，不能由模型直接发 |

未来如果引入本地模型，只做"建议"：建议分类、建议标签、建议摘要，默认关闭，且必须人工确认。届时另写 ADR。

## 指标

- 收集项平均处理时长。
- 收集项积压数量与最老一项的年龄。
- 入档驳回率（说明收集质量）。
- AI 辅助条目的复核覆盖率（目标 100%）。

## 未决问题

- 成员实际使用的 AI 工具清单与隐私政策。
- 是否需要提供统一的脱敏脚本。
- 本地模型是否值得部署。
- 收集箱是否开放匿名提交（例如群聊里任何人可丢资料）。
