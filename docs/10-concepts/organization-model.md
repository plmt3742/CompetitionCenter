# 组织模型

## 现状

部门分为四个组：

- 算法组：算法类赛事的命题、评测、技术保障。
- 开发组：开发类赛事的命题、评审、技术保障。
- 媒体组：宣传、视觉、摄影、推文；成员与算法组/开发组交叉。
- 综合事务组：场地、物资、财务、联络；成员与算法组/开发组交叉。

关键事实：**组不是互斥的**。一个人可以同时在算法组和媒体组，也可以在某场赛事里担任与日常组别不同的角色。因此系统不能用"组"直接做权限边界。

## 三个概念分开

| 概念 | 定义 | 例子 | 变更频率 |
|---|---|---|---|
| 人 Person | 部门成员或外部联系人 | 某位成员 | 低 |
| 组 Group | 长期职能分组 | 算法组、媒体组 | 低 |
| 岗位 Position | 一组职责与交接包的载体 | 赛事负责人、档案管理员 | 中 |
| 任职 Assignment | 某人在某任期担任某岗位 | 张三 2026 学年任赛事负责人 | 高 |
| 赛事角色 EventRole | 在某届赛事中的具体分工 | 2026 算法赛命题人 | 每届 |

原则：**交接的是岗位，不是人**。人毕业了，岗位还在；新任职者接的是岗位包。

## 数据模型

### Person

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `name` | 姓名（L3，不公开） |
| `student_id` | 学号（L3） |
| `contact` | 手机/邮箱（L3） |
| `groups` | 多对多，含主组/交叉标记 |
| `status` | `active` / `alumni` / `external` |
| `joined_at` / `left_at` | 在部门时间 |

### Group

| 字段 | 说明 |
|---|---|
| `id` / `name` | 算法组、开发组、媒体组、综合事务组 |
| `lead_id` | 组负责人 |
| `description` | 职责边界 |
| `is_cross_capable` | 是否允许交叉成员（媒体/事务为是） |

### Position

| 字段 | 说明 |
|---|---|
| `id` / `name` | 岗位名 |
| `scope` | 全局 / 组 / 赛事 |
| `duties` | 职责清单 |
| `recurring_tasks` | 周期任务 |
| `handover_template_id` | 交接包模板 |
| `required_permissions` | 需要的系统权限 |

建议的岗位清单：

- 中心负责人：全局统筹、对外代表、权限最终审批。
- 组负责人：本组人员与产出、跨组协调。
- 赛事负责人：单个届次的总责与档案完整性。
- 命题/评测负责人：赛题、数据、判题/评审标准。
- 宣传负责人：通知、视觉、媒体素材与发布。
- 物资/财务负责人：场地、物资、预算与报销。
- 档案管理员：模板、完整性检查、归档与保留。
- 外联/评委联络：合作方、评委邀请与回避声明。

### Assignment

| 字段 | 说明 |
|---|---|
| `person_id` / `position_id` | 谁担任什么 |
| `term` | 任期，如 2026 学年 |
| `event_id` | 若为赛事岗位，绑定届次 |
| `start_at` / `end_at` | 起止 |
| `status` | `active` / `ended` / `transferred` |

## 权限角色

系统角色与组织岗位分开：岗位可以要求某些权限，但权限由管理员授予。

| 角色 | 范围 | 能做什么 |
|---|---|---|
| 访客 visitor | 公开端 | 浏览 L1、提交咨询 |
| 选手 contestant | 公开端 + 报名 | 报名、查看自己的报名与公开结果 |
| 成员 member | 内部端 | 查看 L2、提交收集项、处理自己被指派的任务 |
| 赛事负责人 event_owner | 指定届次 | 管理该赛事的卷宗、条目、任务、成员 |
| 组负责人 group_lead | 指定组 | 查看本组事务、指派任务、参与交接 |
| 评委/合作方 judge | 指定赛事 | 只读指定 L4 材料、提交评分 |
| 中心负责人 admin | 全局 | 组织、权限、模板、审计、发布审批 |

## 权限矩阵（草案）

| 模块 | 访客 | 选手 | 成员 | 赛事负责人 | 组负责人 | 中心负责人 |
|---|---|---|---|---|---|---|
| 公开门户 | 读 L1 | 读 L1 | 读 L1 | 读 L1 | 读 L1 | 读 L1 |
| 档案 | 无 | 无 | 读 L2 + 被授权 | 读写本赛事 | 读本组 | 全部 |
| 收集箱 | 无 | 无 | 提交/处理自己 | 管理本赛事 | 看本组 | 全部 |
| 赛事 | 无 | 无 | 读 | 管理本赛事 | 读本组 | 全部 |
| 组织 | 无 | 无 | 读成员目录 | 读本赛事成员 | 读本组 | 管理 |
| 交接 | 无 | 无 | 读自己的岗位包 | 生成赛事包 | 生成组包 | 全部 |
| 审计 | 无 | 无 | 无 | 读本赛事 | 读本组 | 全部 |

密级优先于角色：即使有模块权限，L3/L4 仍需额外授权。

## 阶段 RACI（简化）

| 阶段 | 负责 A | 执行 R | 协作 C |
|---|---|---|---|
| 立项筹备 | 中心负责人 | 赛事负责人 | 组负责人 |
| 宣传报名 | 赛事负责人 | 宣传 + 成员 | 媒体组 |
| 赛前准备 | 赛事负责人 | 命题/评测 + 物资 | 评委、场地 |
| 比赛执行 | 赛事负责人 | 现场负责人 + 志愿者 | 媒体组 |
| 评审 | 评审负责人 | 评委 | 赛事负责人 |
| 公示申诉 | 赛事负责人 | 档案管理员 | 评审负责人 |
| 收尾归档 | 赛事负责人 | 档案管理员 | 全组 |

## 交接

- 每个岗位有固定交接包：职责、周期任务、在办、历史入口、联系人、坑。
- 岗位换人时：新任职者先读岗位包，再由旧任职者做一次 walkthrough。
- 权限转移与资料转移分开：先转权限，再转文件所有权，最后双方确认。
- 详见 [`../50-operations/handover.md`](../50-operations/handover.md)。

## 负载视图

按人聚合：当前负责的赛事数、未完成任务数、临近截止、收集箱待处理。用于发现"一个人同时扛三场赛事"这类风险，不做绩效评估。

## 未决问题

- 部门实际人数与组负责人设置。
- 岗位是固定编制还是每届临时指定。
- 成员毕业后的账号与档案保留策略。
- 外部评委/合作方是否需要独立账号。
