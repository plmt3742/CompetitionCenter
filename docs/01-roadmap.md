# 路线图

## 总览

| 阶段 | 目标 | 核心产出 | 退出条件 |
|---|---|---|---|
| P0 设计 | 定模型、边界与优先级 | `docs/` 设计文档、ADR | 维护者评审通过，未决事实补齐 |
| P1 档案 MVP | 跑通一届赛事的档案闭环 | 卷宗、条目、收集箱、检索、权限 | 一届真实赛事完整归档 |
| P2 内部事务与交接 | 让日常事务与换届可查 | 赛事看板、任务、岗位包、交接包 | 完成一次真实换届交接 |
| P3 对外门户 | 对外统一入口 | 公开站点、报名、咨询、发布流程 | 一届赛事对外使用 |
| P4 制度化 | 让系统成为常态 | 模板库、指标、审计、保留策略 | 连续两届赛事复用 |

## P0 设计（当前）

**范围**

- 章程、路线图、档案模型、赛事生命周期、组织模型、AI 协同。
- 功能清单、信息架构、系统总览、技术选型标准。
- 仓库骨架、Git、本地上下文体系。

**不做**

- 不写前后端代码，不定数据库，不部署。
- 不做真实数据迁移。

**退出条件**

- 维护者逐篇评审，删掉不需要的功能，补上遗漏的场景。
- 部门事实（人数、赛事、工具、资料位置）补齐或明确标为未知。
- 技术约束（SSO、服务器、域名）有结论或明确的待验证计划。

## P1 档案 MVP

**范围**

- 卷宗与条目：创建、编辑、版本、密级、状态。
- 收集箱：极简登记、处理状态、入档关联。
- 赛事模板：算法类、开发类各一套；从上一届克隆结构。
- 检索：按赛事、年份、类型、阶段、条目类型、负责人、密级。
- 权限：登录、角色、赛事级授权、L1–L4 过滤。
- 完整性检查：按阶段清单显示缺件与负责人。

**不做**

- 不做报名账号、不做公开门户、不做自动 AI、不做 OJ。

**退出条件**

- 用一届真实赛事从创建卷宗走到赛后归档。
- 档案完整率达到章程目标，且负责人愿意继续用。
- 能导出该赛事的交接包。

## P2 内部事务与交接

**范围**

- 赛事看板：阶段、负责人、截止日期、风险。
- 轻量任务：指派、截止、状态；不做甘特图与工时。
- 通知：内部发布与已读确认。
- 组织：成员、组、交叉身份、岗位与任期。
- 交接：岗位包、赛事交接包、双人核对、权限转移。

**退出条件**

- 完成一次真实换届：新任负责人依靠系统在 1 天内接手。
- 岗位包不依赖某个人的私人网盘。

## P3 对外门户

**范围**

- 公开端：首页、赛事列表/详情、通知、成果、关于、联系。
- 报名：外链表单或内建表单；数据回流到赛事卷宗。
- 咨询：表单/邮箱/FAQ，工单化跟踪。
- 发布流程：内部审校 → 发布 → 下架；只发布 L1。
- 评委/合作方：受控的赛事工作区（可选）。

**退出条件**

- 一届赛事的外部信息只在门户发布一次，其他渠道引用链接。
- 咨询有首次响应时间记录。

## P4 制度化

**范围**

- 模板库与检查清单持续维护。
- 指标：完整率、处理时长、交接时间、咨询响应。
- 审计与保留策略落地。
- 连续两届复用与复盘。

**退出条件**

- 下一届无需重新设计流程，只做模板微调。
- 交接包成为固定动作，而不是临时补材料。

## 里程碑

| 里程碑 | 判定 |
|---|---|
| M0 设计冻结 | P0 退出条件满足，ADR 0001–0006 生效 |
| M1 一届赛事档案闭环 | P1 退出条件满足 |
| M2 一次真实换届 | P2 退出条件满足 |
| M3 一届赛事对外 | P3 退出条件满足 |
| M4 连续两届复用 | P4 退出条件满足 |

## 排期原则

- 以赛事为节拍，不设与赛事无关的虚假日期。
- 每个阶段只承诺一个可验证的结果，不并列铺开。
- 任何阶段发现范围膨胀，先砍功能，不砍档案完整性。
