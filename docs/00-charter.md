# 项目章程

## 一句话

竞赛中心的信息管理与对外协同平台：以赛事届次为聚合根建立档案，用低负担收集解决资料散落，用岗位包解决换届交接，用公开门户完成对外接洽。

## 背景

计算机科学与技术学院竞赛中心负责院内算法类与开发类赛事。部门事务以赛事为单位展开：一场比赛从筹备、报名、赛前准备、执行、评审、公示到收尾，会产生通知、规则、名单、成绩、媒体物料与复盘等大量资料。

当前的主要问题不是"没有资料"，而是：

1. **资料散落**：群聊、网盘、个人电脑、邮件各有一部分，找不到唯一版本。
2. **交接断档**：事务怎么做的、做到哪一步、找谁，长期只存在个人记忆里；换届后从零开始。
3. **对外入口不统一**：通知、报名、咨询分散在不同渠道，选手不知道以哪个为准。
4. **重复劳动**：同一份信息要为内部记录、对外发布、报名表各写一遍。
5. **记录负担**：如果系统要求成员填很多字段，最后一定没人填。

## 服务对象

| 对象 | 需要什么 | 系统给什么 |
|---|---|---|
| 部门成员 | 知道现在有什么赛事、自己负责什么、资料在哪 | 工作台、赛事看板、任务、档案检索 |
| 赛事负责人 | 从筹备到归档有一份清单，不靠记忆 | 赛事卷宗、阶段模板、完整性检查、交接包 |
| 组负责人 / 中心负责人 | 看全局、做交接、控制权限 | 组织与岗位、负载视图、审计 |
| 院内学生 / 选手 | 找到赛事、规则、报名入口、咨询方式 | 公开门户、赛事详情、报名、FAQ |
| 学院 / 合作方 / 评委 | 了解中心、对接合作、参与评审 | 公开介绍、联系入口、受控的赛事工作区 |

## 目标

### G1 数据管理

以赛事届次为聚合根，建立可检索、可版本化、可导出、可交接的档案；每份资料有唯一归属、密级与来源。

### G2 内部事务处理

用赛事看板、轻量任务、通知与岗位包承载日常事务；把"谁负责、到哪一步、缺什么"变成系统里可查的状态，而不是口头约定。

### G3 对外对接协同

用公开门户统一发布赛事信息、报名入口与咨询渠道；对外只读取已审校的 L1 内容，内部档案默认不公开。

### G4 交接（贯穿）

任何岗位与赛事都能导出交接包：职责、在办、历史入口、未决问题、关键联系人。交接不是一次性文档，而是系统的持续能力。

## 非目标

- 不做通用 IM、论坛、视频平台。
- 不做在线评测（OJ）与判题；需要时对接现有 OJ。
- 不做财务、报销、人事、考勤、绩效系统。
- 不做完整的通用 CMS；只做赛事与部门内容。
- 不做自动 AI 归档；AI 处理在个人侧完成（见 ADR-0004）。

## 设计原则

1. **赛事为聚合根**：档案、任务、通知、名单、成绩都挂在具体届次上；非赛事事务用运营卷宗。
2. **档案优先**：流程可以轻，档案必须全；能查到的就不靠口口相传。
3. **低负担收集**：收集箱只填最少字段；批量与移动端优先；不为系统而记录。
4. **内外分离**：公开端只读 L1；内部数据默认不公开；权限按赛事授权。
5. **可迁移**：元数据与文件可整体导出；不把部门资料锁进某个平台。
6. **先模板后流程**：用清单与模板保证下限，不用复杂审批流绑架所有人。

## 约束

- 学生团队，时间碎片化，不能假设每天有人维护。
- 单人统筹 + AI 辅助，方案必须可被下一位维护者接手。
- 仓库公开：设计文档可公开，真实数据与内部判断不可公开。
- 隐私优先：报名表、成绩、联系方式属于 L3；赛题与评审细节属于 L4。
- 不假设学院提供统一认证、服务器或域名；这些是待确认项。

## 成功标准（草案，待维护者确认）

| 指标 | 目标 | 验证方式 |
|---|---|---|
| 赛事档案完整率 | 赛后 14 天内 ≥ 90%（按模板清单） | 系统完整性检查 |
| 新人定位资料 | 1 小时内找到任一赛事的关键资料与在办事项 | 交接演练 |
| 收集项处理时长 | 平均 ≤ 7 天 | 收集箱时间戳 |
| 对外首次响应 | 咨询 2 个工作日内 | 咨询记录 |
| 公开内容合规 | 100% 来自 L1 已审校条目 | 发布前抽查 |
| 换届交接 | 一次完整交接 ≤ 1 天，双方签字确认 | 交接包导出记录 |

## 假设

- 赛事是部门最主要的事务单元，但存在招新、例会等运营事务。
- 媒体组与综合事务组成员与算法组/开发组交叉，人员分组不等于权限分组。
- 成员愿意用手机完成"收集"这一步，但不愿填长表单。
- 报名可以先用外链表单，系统只做结果回流与档案关联。
- 公开门户可以先静态化，不必一开始就做账号体系。

## 未决问题

- 部门人数、每年赛事数量与类型、换届周期。
- 学院是否提供 SSO、服务器、域名与备案支持。
- 现有报名、评测、公示工具及其数据导出能力。
- 历史资料的规模、格式与当前位置。
- 对外门户是否需要选手账号与成绩查询。
- 系统长期维护人与维护预算。
