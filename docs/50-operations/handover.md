# 交接手册

## 为什么交接会失败

1. 事情只存在个人记忆里，没有写下来。
2. 资料在个人网盘/电脑里，没有统一归属。
3. 没有明确"交接什么"，以为吃顿饭就算交接。
4. 权限没有转移，新人进不去系统。
5. 交接完没有核对，缺件几个月后才发现。

系统的目标不是让交接"有个文档"，而是让交接**可查询、可核对、可导出**。

## 两种交接包

| 类型 | 对象 | 内容 | 触发 |
|---|---|---|---|
| 岗位包 | 一个岗位（如赛事负责人） | 职责、周期任务、在办、历史入口、联系人、坑 | 岗位换人 |
| 赛事包 | 一个赛事届次 | 档案完整性、未决事项、下届建议、关键文件 | 赛事收尾或负责人变更 |

## 岗位包结构

| 部分 | 写什么 | 来源 |
|---|---|---|
| 岗位说明 | 一句话职责、边界、汇报关系 | 组织模型 |
| 周期任务 | 每学期/每届固定要做的事与时间点 | 往年记录 |
| 在办事项 | 当前未完成的任务、截止日期、下一步 | 任务系统 |
| 历史入口 | 过去两届同类赛事的卷宗链接 | 档案系统 |
| 关键联系人 | 学院、场地、财务、合作方（角色，不写私人电话） | 本地运营事实 |
| 常见坑 | 每年都会卡的点、踩过的雷 | 复盘与个人记录 |
| 权限清单 | 系统角色、账号归属、需要转移的权限 | 权限系统 |
| 确认 | 交出人、接收人、日期、缺件说明 | 交接记录 |

## 赛事包结构

| 部分 | 写什么 |
|---|---|
| 基本信息 | 赛事、届次、年份、类型、负责人 |
| 完整性 | 必备条目清单、缺件与责任人 |
| 时间线 | 各阶段起止、关键节点 |
| 关键文件 | 规则、通知、名单、成绩、复盘、媒体（manifest + 密级） |
| 未决事项 | 申诉、报销、证书、场地尾款等 |
| 下届建议 | 模板要改什么、哪些流程要提前 |
| 风险 | 数据缺口、权限未转、合作方未确认 |

## 交接流程

| 时间 | 动作 | 产出 |
|---|---|---|
| T-30 天 | 旧任职者生成岗位包/赛事包初稿 | 初稿 |
| T-14 天 | 补全在办、缺件、联系人；确认权限清单 | 完整包 |
| T-7 天 | 新任职者阅读并列出问题 | 问题清单 |
| T-0 | 交接会：逐项过，双方确认 | 签字记录 |
| T+7 天 | 新任职者独立完成一件小事；旧任职者只答疑 | 独立操作记录 |
| T+30 天 | 回看缺件是否补齐 | 更新后的包 |

## 核对清单

- [ ] 岗位/赛事基本信息完整。
- [ ] 在办事项都有下一步与截止日期。
- [ ] 档案完整性检查已跑，缺件有责任人。
- [ ] 关键文件可访问，校验和一致。
- [ ] 系统权限已转移，旧账号已降权。
- [ ] 关键联系人已更新（只写角色与渠道）。
- [ ] 新任职者能独立找到三类资料：规则、名单、成绩。
- [ ] 双方签字，记录归档。

## 系统支持

- 岗位包/赛事包由系统生成初稿，人工补充"坑"与"下届建议"。
- 导出格式：Markdown/PDF 索引 + 文件 manifest（路径、校验和、密级）。
- 大文件不打包，给受控链接；L3/L4 链接带有效期。
- 权限转移与资料转移分开记录，避免"文件给了但账号没给"。
- 交接记录进入审计，作为下一届的参考。

## 指标

| 指标 | 目标 |
|---|---|
| 交接包生成时间 | 赛事结束后 14 天内 |
| 新任独立操作 | 交接后 7 天内完成一件真实任务 |
| 缺件补齐 | 交接后 30 天内 |
| 交接演练 | 每学期至少一次 |

## 岗位包模板

```markdown
# 岗位包：<岗位名>

- 任期：<起止>
- 交出人 / 接收人：
- 更新日期：

## 职责
## 周期任务
## 在办事项
## 历史入口
## 关键联系人
## 常见坑
## 权限清单
## 确认
```

## 未决问题

- 交接是否需要学院/指导老师见证。
- 旧任职者毕业后账号如何处理。
- 交接包是否需要固定归档年限。
