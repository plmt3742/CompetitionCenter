# 系统蓝图

> 按「系统 → 页面 → 功能板块 → 板块设计 → 设计逻辑」组织的落地设计。
> 目标不是画一个演示站，而是一套能被下一届、下一位维护者继续用的系统。

## 五层结构

| 层 | 文档 | 回答的问题 |
|---|---|---|
| 1 系统 | [`01-system.md`](01-system.md) | 系统是什么、由哪些对象组成、边界与全局规则 |
| 2 页面 | [`02-pages.md`](02-pages.md) | 有哪些页面、每页服务谁、由哪些板块组成 |
| 3 功能板块 | [`03-blocks.md`](03-blocks.md) | 每个板块的位置、字段、操作与规则 |
| 4 板块设计 | [`03-blocks.md`](03-blocks.md) | 核心板块的布局、状态、权限、边界与验收 |
| 5 设计逻辑 | [`04-logic.md`](04-logic.md) | 状态机、权限、模板、数据生命周期、导入导出 |
| 长期复用 | [`05-reuse.md`](05-reuse.md) | 跨届次、跨任期、跨维护者怎么复用 |

## 怎么读

- 第一次读：`01-system.md` → `02-pages.md` → `05-reuse.md`。
- 做页面/交互：`02-pages.md` 找页面 → `03-blocks.md` 找板块。
- 写代码前：`04-logic.md` 的状态机、权限、模板规则必须过一遍。
- 评审时：每篇末尾的验收项就是检查表。

## 与现有文档的关系

- 概念模型仍以 `../../10-concepts/` 为准；本目录负责把它们落到页面与板块。
- 功能优先级以 `../20-requirements/features.md` 为准；本目录不新增强度，只补设计。
- 技术选型仍未决策；本目录只描述行为，不绑定框架。

## 设计基线

- 单部门单租户，不按 SaaS 设计。
- 对外只读 L1；内部按角色、范围、密级授权。
- AI 在系统外，系统只做收集与来源登记。
- 档案优先，流程轻量；不做 BPM、OJ、IM、财务/人事。
