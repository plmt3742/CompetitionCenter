# 设计逻辑

> 第 5 层：跨页面、跨板块的规则。页面与板块负责“长什么样”，本文负责“为什么这样、什么时候允许、出了问题怎么办”。

## 1. 状态机

### 卷宗 Case

| 当前 | 动作 | 下一状态 | 谁可以做 | 副作用 |
|---|---|---|---|---|
| draft | 启用 | active | 负责人/管理员 | 生成阶段与清单 |
| active | 进入收尾 | closing | 负责人 | 锁定新条目创建（可配置） |
| closing | 归档 | archived | 负责人/管理员 | 只读；生成归档记录 |
| archived | 重新开启 | active | 管理员 | 写原因；恢复写权限 |
| 任意 | 标记结果 | 不变 | 负责人 | `outcome`: completed/cancelled/merged |

取消赛事不改状态，写 `outcome = cancelled`，保留档案与复盘。

### 阶段 Phase

| 当前 | 动作 | 下一状态 | 谁可以做 | 规则 |
|---|---|---|---|---|
| pending | 开始 | in_progress | 阶段负责人 | 记录开始时间 |
| in_progress | 完成 | done | 阶段负责人 | 提示缺件，不强制阻塞 |
| pending/in_progress | 跳过 | skipped | 负责人/管理员 | 必须写原因 |
| done | 重开 | in_progress | 负责人/管理员 | 写原因 |

### 条目 ArchiveItem

| 当前 | 动作 | 下一状态 | 谁可以做 | 副作用 |
|---|---|---|---|---|
| draft | 提交复核 | in_review | 编辑者 | 通知复核人 |
| in_review | 通过 | active | 复核人 | 生成版本；可发布 |
| in_review | 退回 | draft | 复核人 | 写退回原因 |
| active | 新建版本 | active（新版本） | 编辑者 | 旧版 `superseded` |
| active | 归档 | archived | 负责人/管理员 | 只读；进入保留期 |
| superseded | 归档 | archived | 管理员 | 保留历史 |

### 收集 IntakeItem

| 当前 | 动作 | 下一状态 | 谁可以做 | 规则 |
|---|---|---|---|---|
| captured | 分诊 | triaged | 成员/负责人 | 指定卷宗、阶段、类型、处理人 |
| triaged | 开始处理 | processing | 处理人 | 记录处理工具与时间 |
| processing | 标记可入档 | ready | 处理人 | 必填元数据齐全 |
| ready | 入档 | archived | 复核人 | 生成条目并回链 |
| 任意 | 拒绝 | rejected | 负责人 | 必须写原因 |
| rejected | 重开 | triaged | 管理员 | 写原因 |

### 任务 Task

| 当前 | 动作 | 下一状态 | 规则 |
|---|---|---|---|
| todo | 开始 | doing | 记录开始时间 |
| doing | 完成 | done | 记录完成时间 |
| todo/doing | 取消 | cancelled | 写原因 |
| done | 重开 | doing | 负责人 |

超期是计算状态（`due < now && status != done`），不单独存。

### 发布 Publication

| 当前 | 动作 | 下一状态 | 规则 |
|---|---|---|---|
| 未发布 | 发布 | published | 仅 L1；需审校；写渠道与时间 |
| published | 下架 | unpublished | 写原因；保留记录 |
| unpublished | 重新发布 | published | 新发布记录 |

### 交接 HandoverPackage

| 当前 | 动作 | 下一状态 | 规则 |
|---|---|---|---|
| draft | 提交复核 | in_review | 生成快照 |
| in_review | 退回 | draft | 写原因 |
| in_review | 双方确认 | signed | 记录交出/接收人 |
| signed | 归档 | archived | 只读；可导出 |

## 2. 权限判定

判定顺序（任一不满足即拒绝）：

1. **身份**：已登录且账号有效；外部访客只能读公开端。
2. **角色**：拥有该动作需要的角色或岗位授权。
3. **范围**：全局 / 组 / 赛事；跨范围需显式授权。
4. **密级**：资源密级 ≤ 授权密级；L4 必须单独授权。
5. **状态**：归档只读；已发布条目不可改；授权未过期。
6. **职责分离**：L3/L4 的处理人与复核人不能同一人。

实现要求：

- 所有查询在数据层带密级条件，禁止“查全量再过滤”。
- 前端隐藏按钮只是体验，后端必须再判一次。
- 拒绝返回统一错误，不泄露资源是否存在。
- 越权尝试写审计：谁、什么资源、什么动作、何时。
- 临时授权带到期时间；到期后自动降为只读或无权。
- L3/L4 的处理人与复核人应分离；小团队无法分离时，由管理员批准例外并写原因，记审计。

敏感动作清单：导出 L3/L4、发布/下架、权限授予、删除/归档、重新开启卷宗、批量修改密级。

## 3. 模板、版本与克隆

### 模板

- 模板有 `draft → published → deprecated` 生命周期。
- 卷宗创建时记录模板版本，并快照阶段、清单、默认角色。
- 模板变更生成新版本；旧版本保留，已有卷宗不受影响。
- 升级卷宗必须预览差异，手动确认；不自动迁移历史条目。

### 克隆规则

| 内容 | 默认 | 说明 |
|---|---|---|
| 阶段与清单 | 复制 | 结构复用 |
| 空白表单/规则模板 | 复制 | 需重新确认版本 |
| 复盘与下届建议 | 可选 | 帮助下一届 |
| L1 公开内容 | 可选 | 需重新审校 |
| L3/L4 数据 | 不复制 | 报名、成绩、赛题、评审 |
| 任务与在办 | 不复制 | 重新指派 |
| 权限与成员 | 不复制 | 按新赛事重新授权 |

克隆必须预览，列出将复制/不复制的内容；克隆任务可后台执行，失败可重试。

### 版本

- 条目、模板、字典、交接包都版本化。
- 版本号单调递增；`supersedes_id` 指向被替代版本。
- 已发布内容不可原地修改；更正走新版本，公开端显示最新已发布版本。

## 4. 数据生命周期与保留

```text
收集 → 分诊 → 处理 → 复核 → 入档 → 发布（可选）→ 保留 → 处置
```

| 数据类型 | 默认保留 | 到期动作 |
|---|---|---|
| 赛事档案 L1/L2 | 归档后 3 年 | 归档/可导出后清理 |
| 报名与成绩 L3 | 按学院要求，至少 3 年 | 匿名化或删除 |
| 赛题/评审 L4 | 按赛事要求 | 删除或封存 |
| 审计 | 3–5 年 | 归档 |
| 公开内容 | 长期 | 下架保留内部副本 |

规则：

- 处置前必须导出或确认无保留价值；删除写审计。
- 法律/申诉保留（legal hold）优先于到期清理。
- 软删除后仍有恢复窗口；物理删除只由管理员执行。
- 备份中的删除按备份周期延后生效，需在隐私说明中写清。

## 5. 搜索与索引

- 索引字段：标题、摘要、标签、卷宗、阶段、类型、负责人、年份、状态、密级。
- 文件全文初期不索引；需要时先做 OCR/文本提取，再按密级入索引。
- 查询顺序：权限过滤 → 结构化筛选 → 关键词 → 排序 → 分页。
- 排序：精确标题 > 标签 > 摘要；同分按更新时间倒序。
- 公开端独立索引或强制 `published = true AND classification = L1`。
- 重建索引是后台任务，失败不影响写入；索引延迟可接受（秒级）。

## 6. 导入、导出与去重

### 导出包

```text
export-<scope>-<date>/
  manifest.json        schema 版本、对象数、文件校验和、密级
  cases.json
  items.json
  files/...
```

- 导出按权限过滤；L3/L4 导出需管理员与原因。
- 大文件不重复打包，manifest 给校验和与受控链接。

### 导入流水线

1. 上传 → 2. 字段映射 → 3. 校验 → 4. dry-run 预览 → 5. 提交 → 6. 报告。

- 每批有 `batch_id`，可按批回滚。
- 错误行不阻塞整批；报告给行号与原因。
- 去重：自然键 + 文件校验和；重复项给“跳过/合并/新建副本”。
- 导入不直接发布；进入收集箱或草稿。

## 7. 通知

| 事件 | 收件人 | 渠道 | 去重 |
|---|---|---|---|
| 任务指派/临近截止 | 负责人 | 站内；邮件可选 | 同一任务每天一次 |
| 收集超期 | 处理人/负责人 | 站内 | 每周一次 |
| 复核请求 | 复核人 | 站内 | 每次请求一次 |
| 发布/下架 | 负责人/管理员 | 站内 | 每次一次 |
| 交接到期 | 交出/接收人 | 站内；邮件可选 | 每天一次 |
| 权限即将到期 | 被授权人/管理员 | 站内 | 到期前 7/1 天 |

规则：默认站内；邮件可选；支持摘要；夜间不推送非紧急；可退订非必须通知。

## 8. 审计

- 记录：actor、action、object_type、object_id、before/after 摘要、reason、timestamp、correlation_id。
- 必记：创建、修改、状态迁移、发布、下架、权限变更、导出、删除、越权拒绝。
- 审计只追加；管理员可查；导出审计本身也记审计。
- 活动流是审计的“人话视图”，两者不能矛盾。

## 9. 时间、届次与命名

- 时区 Asia/Shanghai；截止日按当天 23:59。
- 学年/自然年 + 届次；不要把年份写进业务规则。
- slug 发布后不改；改名保留旧 slug 跳转。
- 文件名不写个人信息；用赛事简称 + 年份 + 类型 + 版本。

## 10. 并发、冲突与幂等

- 编辑用版本令牌（乐观锁）；冲突时展示双方摘要，要求人工合并。
- 发布、导入、克隆、交接生成用幂等键；重复提交返回同一结果。
- 上传分片/重试；校验和一致才算完成。
- 后台任务失败可重试；失败原因可见。

## 11. 性能与容量目标

| 场景 | 目标 |
|---|---|
| 内部列表/搜索 | 1 万条目内 < 1s |
| 公开详情页 | 可缓存，首屏 < 2s（4G） |
| 文件上传 | 100 MB 内可断点/重试 |
| 导入 | 1 万行内可分批完成 |
| 并发 | 报名/公示峰值 500 不阻塞 |

## 12. 验收清单

- [ ] 六条状态机的每个迁移都有权限、原因与审计。
- [ ] L3/L4 在列表、搜索、导出、日志、通知中都不泄露。
- [ ] 模板升级不影响历史卷宗；克隆不复制敏感数据。
- [ ] 导出包含 schema 版本与校验和；导入可 dry-run、可回滚。
- [ ] 发布/下架与公开端状态一致。
- [ ] 归档卷宗只读；重新开启有原因。
- [ ] 并发编辑不覆盖；重复提交幂等。
- [ ] 备份恢复演练通过；下一任维护者能照文档操作。
