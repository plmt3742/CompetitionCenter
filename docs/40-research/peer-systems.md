# 同类系统对比框架

## 目的

不是找一个系统照抄，而是判断哪些能力已经被验证、哪些坑别人踩过、哪些不该自己造。当前只建框架，样本与结论待补。

## 四类参照

| 类别 | 代表形态 | 可借鉴 | 不适合直接用的原因 |
|---|---|---|---|
| 高校竞赛管理平台 | 教务/竞赛报名与审核系统 | 赛事字段、报名审核、公示流程 | 通常偏行政流程，档案与交接弱 |
| 在线评测（OJ） | DOMjudge 等 | 榜单、判题、申诉 | 只覆盖算法赛，不含档案与部门事务 |
| 档案/文件管理 | Nextcloud、Seafile、DSpace 类 | 文件版本、权限、保留 | 缺赛事模型与完整性清单 |
| 协作表格/知识库 | Notion、飞书多维表格类 | 低门槛录入、视图、模板 | 权限与公开门户弱，长期有锁定风险 |

说明：以上仅作为候选类型，具体产品能力需在调研时核实，不把宣传页当结论。

## 对比维度

| 维度 | 要回答的问题 |
|---|---|
| 赛事建模 | 是否支持赛事品牌与届次分离？是否支持模板克隆？ |
| 档案元数据 | 是否支持条目类型、密级、来源、版本？ |
| 完整性 | 是否能按阶段检查缺件？ |
| 权限 | 是否支持赛事级授权与密级过滤？ |
| 对外门户 | 是否能只发布 L1？是否可静态化/SEO？ |
| 收集入口 | 是否支持低负担登记与移动端？ |
| 交接 | 是否能导出岗位/赛事交接包？ |
| 导出与迁移 | 元数据与文件能否整体导出？ |
| 成本 | 托管、许可、维护人力 |
| 可维护 | 依赖、升级、文档、社区 |

## 调研方法

1. 每类选 1–2 个样本，合计 4–6 个。
2. 每个样本写一页：定位、核心模型、权限、导出、成本、可借鉴点、不可借鉴点。
3. 只记录可验证的事实，注明来源与访问日期。
4. 最后回答三个问题：
   - 哪些能力直接采用现成方案？
   - 哪些必须自建？
   - 哪些明确不做？

## 初步判断（待验证）

- 赛事与档案模型必须自建，现成系统很难同时满足"届次聚合 + 密级 + 交接"。
- 文件存储、预览、备份可以复用成熟方案，不自造。
- 公开门户可以用静态站/SSR，不需要完整 CMS。
- OJ 只做对接，不自建判题。
- 低代码工具适合做收集原型，不适合作为唯一数据源。
